# 候选任务评估模板

- 候选名称：定时任务运行质量排查与归因
- 任务描述：面对 cron / 定时任务出现超时、未触发、延迟补跑、状态计数异常等情况，先区分"任务配置错误"与"宿主（Gateway / 机器）离线窗口"，再给出处置动作（补跑 / 改配置 / 禁用 / 改频），并留下可复用的排查路径。
- 典型触发场景：连续 timeout、consecutiveErrors 异常清零、任务"没跑"但也无报错、补跑堆叠。
- 关联事件 / 样本：
  - 2026-10-30-cron-triage-w44（本次 W44 周总结，10-29 离线窗口导致周四/周五任务堆叠至 10-30 傍晚补跑）
  - 2026-10-23 W41 周总结（连续 timeout 判定：目标数据源已消亡）
- 最近出现频率：中（近 4 周出现 2 次以上同类排查）
- 单次平均耗时：30-60 分钟
- 主要重复步骤：
  1. 拉取 job 列表 + 运行历史，按时间戳还原本周每一次真实触发/失败
  2. 区分三类原因：配置错 / 宿主离线 / 目标数据源已空
  3. 对"计数器被重置"这类表象做事实核对，避免被状态数字误导
  4. 给出处置：补跑 / 改 schedule / 禁用 / 换数据源
  5. 记录结论并写入决策日志，避免下周重复论证
- 当前痛点：每次排查都要重新翻 cron runs 的时间戳并人工换算成日期；缺少固定判据，容易被 `consecutiveErrors` 之类的表象带偏。
- 预期节省：把"查表 → 归因 → 出结论"压缩到 10 分钟内，避免每周重复写同一份论证。
- 风险点：过度脚本化会丢失对"状态表象 vs 事实"的判断；归因错误会导致误禁用可用任务。
- 推荐沉淀形态：
  - [ ] Skill
  - [x] Prompt
  - [x] Script（仅做时间戳 → 日期换算与 run 汇总）
  - [x] Checklist
  - [ ] 暂缓

## 评分
- 频率（1-5）：3
- 稳定性（1-5）：4
- 节省潜力（1-5）：4
- 维护风险（1-5）：3
- 综合判断：中优先级候选。本周首次出现可复用信号（"补跑堆积"与"计数器重置"两类表象），但样本仍不足，先以 Prompt + Checklist 记录，暂不写脚本。

## 决策
- 是否进入实施队列：
  - [x] 是
  - [ ] 否
- 如果进入，优先级：
  - [ ] 高
  - [x] 中
  - [ ] 低
- 最小实现范围：先写一份排查 Checklist（判据 + 处置矩阵），不动手写脚本。
- 不做范围：不做自动诊断与自动禁用；不做全量 cron 监控平台。
