# 候选任务评估：工具不可用时的降级采集路径

- 候选名称：工具不可用时的降级采集路径
- 任务描述：当某个检索/数据源工具（本次为 `memory_search`）因服务或配置问题不可用时，不等待、不空转，按"事实直采优先级"切换到可用的本地证据源，并明确标注本次事实的采集方式与缺口。
- 典型触发场景：memory_search 报 embedding/provider 错误；或某数据源不可访问但周报/周总结必须按时交付。

## 关联事件 / 样本
- 2026-11-05（周四周报 run）：`memory_search` 报 embedding 错误不可用，改用 git / cron / 系统状态直采
- 2026-11-06（W45 周总结）：`memory_search` 再次返回 `disabled=true, unavailable=true, fetch failed`，同样改用直采
- 样本数：2（连续两周，同一工具）

## 事实直采优先级（本周实际有效的顺序）
1. `git log`（各仓库提交事实）
2. cron jobs / runs（调度事实、任务状态）
3. 系统状态（`launchctl`、`last`、负载、进程）
4. 文件系统产物（Obsidian 归档目录、仓库 logs）
5. 记忆检索（**不可靠，置于最后**，不可用时不影响交付）

## 主要痛点
- 工具不可用时容易被"等工具恢复"拖住，或在总结里留下空洞的"历史情况未知"。
- 缺少一条明确的降级顺序，导致每周重新判断"该查什么"。

## 预期节省
把"工具挂了怎么办"从每次临场判断压缩为一条固定顺序，交付不中断、事实不缺失。

## 风险点
- 降级路径只覆盖机器可直采的事实；**用户侧的真实工作进展、风险与计划仍需 Neo 补充**，不能由系统推断替代。
- 过度依赖直采可能遗漏只有记忆库才有的历史判断（例如已被修正的历史归因）。
